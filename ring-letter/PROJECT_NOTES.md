# Ring letter MVP

Mobile-first anonymous story reading and submissions. Vinext + D1 on the owner's Cloudflare account (ringletter.wetrytrysee.cc, live since v1.0.0 on 2026-11-12). The bundled reading samples (data/matching.ts) are fictional and labelled 範例信 · 虛構示範; the public mailbox has no demo stories. Only author-consented, manually approved submissions are publicly readable. No AI API calls, messaging, or external analytics.

Public users receive an HttpOnly random session cookie; only its SHA-256 hash is stored. Sessions slide (v2 V3-c, issue #4 §6.2): the cookie lasts one year and is re-issued by worker/index.ts on every response to a request carrying a live cookie (pages and API alike, except routes that set or clear it themselves), and sessions.last_seen is moved forward at most once a day; a session is valid, and kept by retention, until one year after its last visit. Reading pages never creates a session; only writing, submitting and feedback do. 我的片段 offers 在這台裝置登出 (DELETE /api/session: deletes the session row and clears the cookie; the stories, feedback and attempts stay and expire under their own rules; without a session it still clears the cookie and returns 200), for shared devices; a later submission from that browser starts a new identity. Losing the cookie (cleared, other device, more than a year away) loses self-service access: the author emails the public contact address ringletter@wetrytrysee.cc (Cloudflare Email Routing; footer, privacy notice and 我的片段) with the title, part of the text or the approximate date, and an admin deletes the story in /admin (rather delete too much than too little), usually within 7 days, and replies. Retention (issue #4 §6): a daily Cron Trigger (17 19 * * * UTC, 03:17 Taipei; lib/server/retention.ts) deletes expired rows in one D1 batch; creating a session purges nothing, and every read (public list, feedback eligibility, 我的片段, admin lists) applies the same SQL (EXPIRES_FROM / LIVE in lib/server/db/stories.ts), so an expired row is invisible before the Cron removes it. Stories keep the terms of the consent version they were submitted under (prefix of stories.consent): under the old "30 days" wording (v2-2026-11-05, legacy or empty), every story, approved included, is hidden and deleted 30 days after creation, and later status changes never extend that; under a version in PERMANENT_CONSENT_VERSIONS (v3-2026-11-12), approved stories are never deleted automatically (only by withdrawal, erase-all or admin delete) and other statuses expire 30 days after their last status change (status_at). Every submission since V3-c (2026-11-12) uses v3-2026-11-12, whose consent wording says so (components/write/ConsentFields.tsx); earlier stories keep their stored consent string and their 30-day terms, nothing is migrated. Deleted stories (withdrawal, erase-all, admin delete, batch delete, expiry: all through deleteStoryRows()) take their feedback and consent history with them; feedback and writing attempts expire 30 days after creation, sessions one year after COALESCE(last_seen, created), admin_events one year after creation whether or not the target still exists. Consent history is kept in the append-only consent_events table (one row per submit/share/unshare, with the consent wording version). Share/unshare rows also carry consent_events.owner (the session hash; migration 0006, nullable, indexed with created) because the daily sharing limit counts them: when a story is withdrawn or deleted by an admin, its owner rows from the last 24 hours are kept (keptForLimit()) so withdrawing does not reset the count, and the first retention run after that day deletes them; erase-all deletes them at once with the session. Older rows without an owner are counted through their story as before. Limits are per session, not a bot-defense guarantee.

Fonts (v2 V5-b, issue #4 §10 item 6): Noto Serif TC is self-hosted from the Worker's static assets (@fontsource/noto-serif-tc, weight 400 only, 108 unicode-range woff2 slices of which a page loads only the ones its characters need), so visitors no longer contact Google Fonts. No fixed-charset subsetting: the characters of submissions cannot be known in advance, and a missing glyph would mix typefaces within one sentence.

Turnstile (v2 V4, issue #4 §5.1): because a script can mint a new session per request, submitting a letter (POST /api/me/stories) and feedback (POST /api/feedback) also need a Cloudflare Turnstile token in X-Turnstile-Token, checked after the same-origin and body checks and before the session (so bots never reach D1); writing starts, sessions, sharing changes and deletes do not. The widget is invisible (interaction-only) unless Cloudflare needs the visitor, loads only with the write form or an opened feedback box, and fetches its token at submit time (tokens last five minutes and are single-use; the widget is reset after every request). A 403 with code "turnstile" is retried once with a new token; the text stays in the form either way. siteverify must say success, the expected action and the hostname in TURNSTILE_HOSTNAME (ringletter.wetrytrysee.cc); unreachable, timed out (5 s), a missing secret or, in production, a missing TURNSTILE_HOSTNAME is 503, never a skipped check. The site key and hostname are wrangler.jsonc vars, the secret key is the Worker secret TURNSTILE_SECRET_KEY, and deploy.yml refuses to deploy when any is missing or the site key is still the placeholder (README.md, Turnstile). The privacy notice says 送出時使用 Cloudflare Turnstile 確認不是自動程式. `npm run dev` always uses Cloudflare's always-pass test keys (inside import.meta.env.DEV, compiled out of production) and checks neither action nor hostname, which the test keys don't report; Playwright serves a fake api.js. Turnstile is not a guarantee either: WAF rate limiting by IP is the next step if writing starts or sessions get flooded.

API (v2, REST, no compatibility with the v1 /api/letter actions): public GET /api/stories, POST /api/session and DELETE /api/session (log out on this device); anonymous-session POST /api/writing-attempts, POST and GET /api/me/stories, DELETE /api/me/stories/:id, PATCH /api/me/stories/:id/sharing, DELETE /api/me, POST /api/feedback; admin (issue #4 §5.2; there is no queue endpoint, every list is cursor-paged) GET /api/admin/summary, GET /api/admin/stories (status, reshare, consent v2/v3, expiring, q, Taipei from/to, id; 50 per page by cursor; same retention rules as every read; each row with expiresAt, terms and feedbackCount), POST /api/admin/stories/:id/moderation (an expired story waiting for deletion can be neither approved nor rejected: 400, or missing in a batch, so a decision never resets its deadline or makes it permanent), GET /api/admin/feedback, DELETE /api/admin/feedback/:id, POST /api/admin/moderation (batch reject or delete, per-story results, never batch approval) and GET /api/admin/events. Admin operations (approve, reject, delete story, delete feedback) are logged in admin_events with the verified Access email, the action, the target id and the time, never content, titles or sessions; a row is written in the same batch as the change and only when the change happens, survives the deletion of its story, and is deleted after a year (stated in the privacy notice). Author withdraw and erase-all are not logged. Every POST, PATCH and DELETE is same-origin checked. Admin access: the admin UI is /admin and the admin API lives under /api/admin/. In production both are behind a Cloudflare Access application, and the Worker independently verifies the Access JWT and requires the email to be in the ADMIN_EMAILS secret (lib/server/auth.ts, lib/server/access-jwt.ts); missing config denies all admin requests. Plans and their records: GitHub issue #2 (v1) and #4 (v2, closing spec #30). In `npm run dev` there is no Access: an identity is only granted to requests carrying the per-run dev secret (.wrangler/dev-admin-token), never based on source address, because tunnels and port forwards arrive from loopback. Anonymous sessions can submit at most 5 stories, 30 feedback events, 30 writing starts and 10 sharing changes per day. Sharing is not fixed at submission (v2 V3-b, issue #4 §6.1): in 我的片段 the author can ask to share a private or rejected story (改為分享 / 再次申請分享: the three consent boxes, current wording, ticked again; the story moves onto the current consent version and goes back to pending, never reusing an earlier approval) or stop sharing a pending or approved one (停止分享: private at once, off the public list, approved_at cleared, consent version kept). Any other combination is 409; each story may ask to share at most 3 times after submission (share events in consent_events), after which the button is disabled but stop sharing and withdraw remain. Each change writes a share/unshare consent event and sets status_at, so a story that stopped sharing expires under its consent version's rule for non-approved stories. The admin story list marks pending stories that asked again (「重新申請分享」) with their consent history count, and the admin UI sends each decision with the statusAt it displayed: an approval or rejection of a story that changed since (e.g. stopped and re-shared) is refused with 409, so nothing is approved unseen; the UI then re-fetches only that story, updates its card in place and says 「這篇剛剛改變了，請再看一次」 (no full reload, filters and scroll kept). Admin UI (V6-b): summary → filters → story list → feedback → operation log. The filters live in the URL (/admin?status=…&reshare=1&consent=v2|v3&expiring=7&q=…&from=…&to=…&id=…), so reload, back/forward and shared links keep them; a story id pasted into the search box becomes an exact id lookup in all statuses. Cards show the story id, submission date, consent version and 剩 N 天 (none for stories kept until withdrawn), for checking a deletion request; after a delete the notice quotes 已刪除《title》（date）. Feedback can be filtered by kind and by story (a card's 看回饋（N）), shows the story title from the API (文章已不在系統中 for gone stories, 已移除的示範故事 for leftover feedback on the removed demo-… stories, which expires by mid-December 2026), links to the story's card, and can be deleted one at a time after a confirm. The operation log can be filtered by admin; live stories link to their card, gone targets show （已刪除）. Batch actions (V6-c): every card has a checkbox; 不通過或下架 sends only the ticked pending/approved stories (disabled with the reason when none are ticked) and 永久刪除 sends all ticked ones; there is never a batch approval, since every story must be read before it goes public. 全選 ticks only the loaded cards (勾選前 50 篇 when more than 50 are loaded), a filter change clears the selection, and each button refuses more than 50 stories to send (reject counts the rejectable ones, delete all ticked) with a message instead of cutting short. While a batch or single moderation runs, the filters and 載入更多 are disabled; after a filter change nothing can be ticked until the new list arrives. A confirm lists the count and the first titles. Each story is sent with the statusAt/consentEvents its card showed and gets the single-story rules. The outcome is applied as soon as the response arrives: done deletes leave the list; done rejections leave it too unless the status filter is 暫不分享 or 全部, where they are re-fetched in place; refused ones stay ticked with the reason on the card (剛剛改變了 / 這個狀態不能不通過 / 已不存在) and are re-fetched (gone ones leave the list; a failed re-fetch keeps the card with a note), and a notice sums it up (已永久刪除 N 篇；M 篇未處理（…）). A page that was requested before a card was removed does not bring it back. Private stories cannot be approved. No admin text editing: changed author consent would otherwise be needed.

Browser QA and API checks are local. tests/api.mjs uses the dev-only admin identity header ONLY against the local dev server (production builds compile that path out); never enable any header-spoofing convenience route in production. Test stories are removed after tests. Browser tests (Playwright, tests/e2e, `npm run test:e2e`) run in the official Playwright container against `npm run dev` too; see README.md.

Before wider release: add stronger abuse prevention, recoverable author identity if needed (a private per-story management link is the next step if admin-assisted deletions become frequent), scoped reviewer membership, and a real author content library. Readership is not automatically measured: feedback counts are events, not unique people or retention.

## V5-a: confirm dialog, write draft, public mailbox (2026-11-14)

Every confirm is the site's ConfirmDialog (components/common/ConfirmDialog.tsx, native <dialog> with showModal), never window.confirm(): 取消 has focus, Esc / backdrop / a route change answer no, focus returns to the button that asked, destructive answers use .danger and verb labels; the wording of each question is unchanged. The unsent /write letter is kept per letter type in sessionStorage only (never localStorage, never sent): title, era, the three questions, original text or body, mood, reflection and the source choice, plus the writing attempt id so a reload or a visit elsewhere continues under the same attempt (no second start in the metrics); the consent boxes and Turnstile are not kept. It is cleared after a successful submit, when the author confirms 重新選擇寫法, and on logout / erase-all in 我的片段. If the attempt is gone (tab open past 30 days, a new session), submit answers 400 code "attempt" and the form starts a new attempt, keeps the text and asks for another submit. The privacy notice and the chooser say unsent text stays only in the tab. /archive is now the official public mailbox in the main navigation (公開信箱; the footer link 先前公開信箱 is gone): the three AI demo stories were removed, feedback no longer accepts their demo-… ids (404), and with nothing approved the page shows an empty state pointing to /read and /write.
